# JobPilot 当前项目状态

> 更新时间：阶段 5 完成并完成专项收敛后。本文用于快速了解项目目前已经完成的业务闭环、模块状态、工程质量沉淀和下一阶段方向。

## 1. 项目定位

JobPilot 是一个 FastAPI 后端工程项目，围绕招聘岗位数据建立：

```text
岗位情报 → 技能分析 → 学习准备
```

完整主线：

```text
外部岗位数据
  -> 清洗、去重、结构化存储
  -> 岗位搜索、筛选、技能标签统计
  -> 用户收藏岗位、设为目标岗位
  -> 对比岗位技能与用户技能画像
  -> 识别 matched / weak / missing 技能
  -> 生成学习任务、练习题目
  -> 记录作答、跳过、进度和任务状态
```

项目重点不是投递管理，也不是重 AI 项目，而是通过真实业务闭环展示后端能力：认证鉴权、数据建模、复杂查询、事务一致性、用户数据隔离、索引设计、日志、测试、缓存和异步任务。

## 5. 已沉淀的工程规范

### 5.1 查询与归档状态

当前已经明确：

| 模块                   | 对外查询参数        | 默认查询范围               |
|----------------------|---------------|----------------------|
| `job_posts`          | `statuses`    | `open`               |
| `job_targets`        | `statuses`    | `active + paused`    |
| `user_skills`        | `statuses`    | `active`             |
| `study_tasks`        | `statuses`    | `todo + in_progress` |
| `job_collections`    | 不提供 status 查询 | `active`             |
| `collection_folders` | 不提供 status 查询 | `active`             |
| `knowledge`          | 不提供 status 查询 | `active`             |
| `questions`          | 不提供 status 查询 | `active + approved`  |

普通用户默认看不到 archived、removed、deleted、draft、rejected 数据。

### 5.2 索引设计

已进行静态索引专项审查，方向是：

1. 保留业务正确性约束和核心查询路径索引。
2. 删除当前没有明确查询路径的提前索引。
3. 避免低选择性字段单列索引。
4. nullable unique 使用 partial unique index。
5. 列表分页排序索引尽量补稳定 tie-breaker。
6. 不为 `ILIKE '%keyword%'` 提前加普通 B-tree 文本索引。

索引优化说明已单独沉淀在索引专项文档中。

### 5.3 日志管理

已补充核心业务写操作日志，当前约定：

1. 查询接口不大量打日志。
2. service 层记录关键业务事件。
3. repository 层只在复杂写入或异常分支记录必要日志。
4. 日志不记录密码、token、完整请求体、答案正文、备注等敏感或大文本。
5. 日志事件要能定位模块、用户、资源和结果。

### 5.4 测试重点

测试目标不是追求覆盖率数字，而是约束业务流程：

1. 用户数据隔离。
2. 软删除/归档默认不可见。
3. 恢复型 upsert 不重复建记录。
4. 学习任务生成幂等复用。
5. 作答/跳过后进度正确更新。
6. 任务完成或归档后不能继续作答。
7. 错误请求不能产生部分写入。
8. 查询参数边界稳定。

## 6. 当前仍需注意的问题

这些不是阻塞业务闭环的问题，但进入后续阶段时需要继续处理：

1. **真实爬虫和 worker 消费链路未完全展开。** 当前更偏 seed/ingestion service，后续需要 Celery 任务编排、失败重试和重复消费处理。
2. **缓存阶段尚未正式开始。** 阶段 6 需要围绕 Cache Aside 做缓存 key、TTL、写后删缓存、空值缓存和缓存一致性测试。
3. **部分查询可以继续做投影优化。** 例如工作台列表返回展示快照字段、减少前端二次查询。
4. **作答历史、掌握度聚合、复习调度暂未实现。** 这些属于学习系统后续增强，不是当前 MVP 核心闭环前置条件。
5. **生产级观测暂未展开。** 目前已有基础日志，后续再考虑指标、链路追踪、告警。
6. **异常体系已经完成核心资源收敛。** 后续新增模块继续沿用模块专属异常类，避免直接抛通用原始异常。

## 7. 下一阶段建议

### 阶段 6：Cache Aside 缓存优化

推荐先做：

1. 岗位详情缓存。
2. filter-options / 热门技能缓存。
3. knowledge tree 缓存失效策略。
4. 学习任务进度是否缓存要谨慎，用户私有数据先不急。
5. 写操作后删除相关缓存，数据库仍是最终事实来源。

1. 新增模块继续保持模块化异常类。
2. 查询模式和 search tools 统一。
3. 事务边界和用户隔离继续补测试。
4. 日志事件命名保持统一。
5. 文档和 README 保持同步。

## 8. 当前项目可以如何对外描述

可以概括为：

> JobPilot 是一个基于 FastAPI、SQLAlchemy、PostgreSQL、Redis、Celery
>
的招聘岗位情报与求职准备平台。系统围绕岗位数据摄入、清洗去重、岗位搜索筛选、技能标签、用户目标岗位、技能差距分析、学习任务生成、题目练习和进度记录形成后端业务闭环。项目重点体现认证鉴权、复杂查询、数据库约束、用户数据隔离、事务一致性、索引设计、日志测试和容器化部署等后端工程能力。
