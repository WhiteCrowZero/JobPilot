# JobPilot 开发规范补充

## 异常

1. service 不直接 `raise NotFoundError(..., code=...)` 或 `ConflictError(..., code=...)`。
2. 核心资源的 NotFound/Conflict 必须落到本模块 `exceptions.py`，并继承 `core.exceptions` 中的统一异常基类。
3. HTTP 层不抛业务异常；router 只做入参映射，异常由 service/repository 业务链路抛出。

## status 查询

1. `job_posts`：对外参数为 `statuses`，默认只查 `open`。
2. `job_targets`：对外参数为 `statuses`，默认只查 `active + paused`。
3. `user_skills`：对外参数为 `statuses`，默认只查 `active`。
4. `job_collections`、`collection_folders`、`knowledge` 不提供 status 参数，默认只查 `active`。
5. `questions` 不提供 status 参数，默认只查 `active + approved`。

## Schema 防护

1. 所有外部输入都要给出明确上限：字符串长度、列表长度、数字范围、耗时范围、分页范围。
2. path id 和外部传入的资源 id 必须为正数。
3. 日期字段必须校验业务边界；开始时间不能晚于结束时间。
4. 用户不可写派生字段，例如 progress、score、completed_count 等只能由业务动作计算。
5. 短数字领域值可在 schema/contract 层使用 `IntEnum` 表达含义，数据库仍保留整数 CHECK。

## upsert

1. 软删除/归档恢复类 upsert 统一使用 `db.upsert.upsert_restoring_record()`。
2. 字典表、摄入幂等、关系替换等非软恢复语义可以继续使用原生 `pg_insert`。
3. 恢复或更新时默认保留旧值，只有请求显式提供的字段才允许覆盖。

## 事务与隔离

1. 公开业务入口统一通过 UoW 管理事务，service/repository 不自行提交。
2. 用户私有资源查询和写入必须带 `user_id`。
3. 子资源写入前必须校验父资源归属，例如收藏所属收藏夹、目标来源收藏、任务内题目。
4. 多表写入必须在同一事务内完成；`study_tasks` 的 attempt/skip/question/progress 更新必须作为一个原子链路。

## 数据库约束

1. nullable 字段需要唯一语义时，优先使用部分唯一索引表达真实业务条件。
2. 枚举字段统一使用 `enum_column()` 生成数据库 CHECK，避免模型枚举和数据库约束漂移。
3. status 与时间戳存在生命周期绑定时，优先使用 CHECK 固化，例如 active 对应归档时间为空。

## 测试

1. 核心闭环至少覆盖成功路径、NotFound/Conflict、用户隔离、默认 status、schema 防护。
2. HTTP 测试只保留契约和入参校验；复杂业务行为优先放到 integration/service 测试。
