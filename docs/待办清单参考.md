# JobPilot 下一阶段待办清单

## P0-1：UserSession 表与会话管理

### 任务

- [ ] 新增 `user_sessions` ORM 模型和 Alembic 迁移。
- [ ] 登录时创建 session，并保存 `session_jti`、`current_refresh_jti`、`refresh_token_hash`。
- [ ] Access Token / Refresh Token 增加 `session_jti`。
- [ ] Refresh 接口基于 session 校验并轮换 refresh token。
- [ ] 支持 logout 当前设备。
- [ ] 支持 logout-all 全部设备。
- [ ] 支持 session list 和踢掉指定设备。
- [ ] Access token blacklist 写入 Redis。
- [ ] 用户禁用后拒绝已有 token 访问。

### 验收

- [ ] 旧 refresh token 不能重复使用。
- [ ] 并发 refresh 只有一个成功。
- [ ] logout 后当前 access token 立即失效。
- [ ] logout-all 后所有设备都不可刷新。
- [ ] 被踢掉的 session 不能继续访问业务接口。

## P0-4：技能匹配与学习任务闭环

### 任务

- [ ] 岗位导入后自动同步 `JobPostSkill`。
- [ ] 技能抽取结果映射到标准 `skill_id`。
- [ ] 统一 `required_level` 和 `proficiency_level` 的匹配规则。
- [ ] 根据目标岗位输出 matched / weak / missing。
- [ ] 学习任务生成只处理 weak / missing 技能。
- [ ] 学习任务使用 `source_key` 防重复生成。
- [ ] 作答后按 skill 聚合结果更新 `mastery_score`。

### 验收

- [ ] 用户缺技能时输出 missing。

- [ ] 生成任务时只选 weak / missing 技能。
- [ ] 题库不足时记录 skipped reason。
- [ ] 重复点击生成不会生成重复 pending / in_progress 任务。
- [ ] 完成任务后用户技能评级有规则化更新。
