## P0-1：生成学习任务时必须校验 target_id 存在且属于当前用户

### 问题

当前：

`POST /learning/study-tasks/targets/{target_id}/generate`

当 `target_id` 不存在或不属于当前用户时，会返回 200 空结果。

### 要求

新增目标岗位存在性校验：

* target 不存在或不属于当前用户：返回 404。
* target 状态不在当前有效目标状态范围内：返回 404 或 400，项目内保持一致即可。
* target 存在但没有 missing/weak 技能缺口：返回 400 `NO_SKILL_GAP_AVAILABLE`，或明确返回空结果；优先使用已有
  `NoStudyTaskSkillGapAvailableError`。

### 修改建议

在 `StudyTaskRepository` 增加方法：

```python
async def get_current_target_for_generation(
        db: AsyncSession,
        *,
        user_id: int,
        target_id: int,
) -> JobTarget | None:
    ...
```

在 `StudyTaskService.generate_from_target()` 开头先调用它。

### 测试

新增或修改测试：

* `generate from missing target returns 404`
* `generate from target owned by another user returns 404`

不要继续让不存在的 target 返回 200 空响应。

## P0-2：手动创建任务失败时不要返回 501 Not Implemented

### 问题

当前 `StudyTaskService.create_task()` 中：

```python
if task is None:
    raise StudyTaskOperationNotImplementedError("Manual study task creation is reserved")
```

但手动创建已经实现。`None` 可能表示 skill 不存在或 question_ids 无效。

### 要求

移除 `StudyTaskOperationNotImplementedError` 在手动创建流程中的使用。

### 修改建议

新增异常：

```python
class StudyTaskSkillNotFoundError(NotFoundError):
    code = "STUDY_TASK_SKILL_NOT_FOUND"


class InvalidStudyTaskQuestionError(BadRequestError):
    code = "INVALID_STUDY_TASK_QUESTION"
```

或者复用项目已有 Skill/Question 异常。

repository 不要只返回 `None` 表达多种失败原因。可以：

* service 先校验 skill；
* service/repository 校验 question_ids；
* 不合法直接抛明确异常。

### 测试

新增：

* invalid skill_id returns 404
* invalid question_ids returns 400/404
* valid manual task creates task and progress

## P0-3：自动练习任务只允许自动判分题型

### 问题

当前生成任务时没有过滤题型，`interview_open` 题目可能进入任务。提交文本答案后，当前 `_grade_attempt()` 会直接返回
incorrect。

### 要求

MVP 阶段只支持自动判分题型进入 `QUESTION_PRACTICE` 任务：

* `single_choice`
* `multiple_choice`
* `true_false`

开放题仍可以在 `/learning/questions/{id}` 查看，但不要进入自动练习任务。

### 修改建议

在 `StudyTaskRepository.list_question_candidates_for_skill()` 增加：

```python
Question.question_type.in_(
    (
        QuestionType.SINGLE_CHOICE,
        QuestionType.MULTIPLE_CHOICE,
        QuestionType.TRUE_FALSE,
    )
)
```

手动创建 `QUESTION_PRACTICE` 任务时，也要校验 question_ids 对应题型在上述范围内。

如果后续要支持开放题，另开设计，不要在本次修复中扩展。

### 测试

新增：

* generated task ignores interview_open questions
* manual question_practice rejects interview_open question

## P0-4：提交作答时校验 selected_option_ids 属于当前题目

### 问题

当前 `_grade_attempt()` 不校验用户提交的 option_id 是否属于当前 question。

### 要求

提交选择题作答时：

* selected_option_ids 必须全部属于当前 question 的 options。
* single_choice 只能选择 1 个。
* true_false 只能选择 1 个。
* multiple_choice 至少选择 1 个。
* 非法请求不能写入 attempt。

### 修改建议

在 `_grade_attempt()` 中读取：

* question_type
* 当前题目的全部 option ids
* 当前题目的 correct option ids

校验失败时抛 `BadRequestError`，例如：

```python
class InvalidStudyTaskAnswerPayloadError(BadRequestError):
    code = "INVALID_STUDY_TASK_ANSWER_PAYLOAD"
```

### 测试

新增：

* selected option from another question is rejected
* selected nonexistent option is rejected
* single_choice with multiple selected options is rejected
* valid correct selected option records correct attempt

## P1-1：生成任务时 max_tasks 应按成功创建/复用数量截断

### 问题

当前逻辑：

```python
for gap in selected_gaps[:payload.max_tasks]:
    ...
```

如果前几个 gap 没题，后面的有效 gap 永远不会被处理。

### 要求

遍历全部 selected_gaps，直到：

```text
created_count + reused_count >= max_tasks
```

无题目的 gap 只计入 skipped，不占用 max_tasks 名额。

### 测试

新增：

* first gap has no questions, second gap has questions, max_tasks=1 should still create one task

## P1-2：填充 skipped_items

### 问题

response 已有 `skipped_items` 字段，但 service 没有填充。

### 要求

```python
StudyTaskGenerationSkippedItem(
    skill_id=gap.skill_id,
    skill_name=gap.skill_name,
    reason="no_question",
)
```

`reused_count` 不需要写入 skipped_items。

### 测试

新增：

* no-question gap appears in skipped_items

## P1-3：更新 StudyTaskProgress.score

### 问题

`progress.score` 目前一直是 `None`。

### 要求

MVP 定义：

```text
score = correct_count / (correct_count + incorrect_count) * 100
skipped_count 不进入分母
没有 correct/incorrect 时 score = None
```

每次 submit/skip 后重新计算。

skip 不改变 score，除非此前没有有效作答。

### 测试

新增：

* correct answer sets score to 100
* incorrect answer sets score to 0
* skip only keeps score None
* correct + incorrect results in 50

## P1-4：限制 StudyTask 状态流转

### 问题

当前 PATCH 可以任意修改状态，包括 archived -> todo、completed -> todo。

### 要求

MVP 只允许：

```text
todo -> in_progress
todo -> completed
in_progress -> completed
todo/in_progress/completed -> archived
```

暂不支持：

```text
archived -> *
completed -> todo
completed -> in_progress
```

### 修改建议

新增状态流转校验方法：

```python
def _validate_task_status_transition(current: StudyTaskStatus, target: StudyTaskStatus) -> None:
    ...
```

非法流转抛 `BadRequestError`。

### 测试

新增：

* archived task cannot be restored through PATCH
* completed task cannot be reopened through PATCH
* todo can become in_progress
* in_progress can become completed

## P1-6：手动绑定题目必须关联当前 skill

### 问题

当前手动创建任务只校验题目 active + approved，没有校验题目是否关联 task.skill_id。

### 要求

当传入 `question_ids` 时，每个 question 必须至少有一条：

```text
QuestionSkill.question_id = question_id
QuestionSkill.skill_id = payload.skill_id
```

否则拒绝。

### 测试

新增：

* question linked to another skill is rejected
* question linked to current skill is accepted
